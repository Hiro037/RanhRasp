# Техническое задание: воссоздание RanhRasp как VK-бота

## 1. Цель продукта

Создать VK-бота расписания для студентов, который:

- хранит профиль пользователя и выбранную учебную группу;
- показывает расписание на выбранную дату текстом и/или картинкой;
- позволяет листать даты вперед/назад;
- принимает обратную связь от студентов;
- дает администратору инструменты загрузки расписания из `.doc/.docx`;
- предоставляет веб-интерфейс и HTTP API для просмотра и ручного управления справочниками.

## 2. Роли

### Студент

- запускает бота;
- выбирает направление и группу;
- смотрит расписание на сегодня, завтра и произвольную дату в доступном диапазоне;
- меняет группу;
- отправляет отзыв.

### Администратор

- загружает расписание по группе и месяцу;
- видит статистику пользователей и запросов;
- очищает кэш изображений;
- управляет группами, преподавателями, предметами и занятиями через веб-интерфейс.

## 3. Основные сценарии VK-бота

### 3.1 Первый запуск

1. Пользователь пишет боту `Начать` или нажимает кнопку сообщества.
2. Бот создает запись пользователя по `vk_user_id`.
3. Если группа не выбрана, бот показывает клавиатуру направлений:
   - Экономика;
   - Менеджмент;
   - ГМУ;
   - Юриспруденция.
4. После выбора направления бот показывает группы этого направления.
5. После выбора группы бот сохраняет группу в профиле пользователя и предлагает выбрать дату.

### 3.2 Повторный запуск

1. Бот находит пользователя по `vk_user_id`.
2. Если группа уже сохранена, бот показывает главное меню:
   - `📅 Посмотреть расписание`;
   - `🔄 Сменить группу`;
   - `ℹ️ Помощь`.

### 3.3 Просмотр расписания

1. Пользователь выбирает пункт просмотра расписания.
2. Бот показывает кнопки дат на ближайшие 8 дней.
3. После выбора даты бот получает занятия из БД по группе и дате.
4. Если возможно, бот отправляет PNG-картинку расписания.
5. Если генератор картинок недоступен, бот отправляет текстовый fallback.
6. Под расписанием показываются кнопки:
   - назад на предыдущий день, если дата больше сегодняшней;
   - вперед до предельной даты;
   - выбрать другую дату;
   - выйти в главное меню.

### 3.4 Загрузка расписания администратором

1. Администратор запускает команду загрузки.
2. Бот проверяет `ADMIN_ID`/список администраторов.
3. Администратор выбирает группу и месяц.
4. Бот просит загрузить `.doc` или `.docx`.
5. Для `.doc` выполняется конвертация через LibreOffice.
6. Парсер извлекает дату, время, предмет, тип занятия, преподавателя и аудиторию.
7. Перед импортом старые занятия выбранной группы в затронутом диапазоне дат удаляются.
8. Новые занятия импортируются идемпотентно.
9. Кэш картинок выбранной группы очищается.
10. Администратор получает отчет: группа, период, количество импортированных и пропущенных занятий.

### 3.5 Обратная связь

1. Пользователь нажимает кнопку/команду обратной связи.
2. Бот переводит пользователя в состояние ожидания текста.
3. Сообщение пересылается администратору с данными пользователя и группы.
4. Если администратор не настроен, пользователь получает явное предупреждение.

## 4. Функциональные требования

### 4.1 VK-адаптер

- Использовать VK Callback API или Long Poll API.
- Изолировать VK SDK от бизнес-логики через интерфейс `BotAdapter`.
- Все обработчики должны вызывать сервисы приложения, а не работать напрямую с БД.
- Клавиатуры VK должны строиться из платформенно-независимой модели кнопок.

### 4.2 Расписание

- Получение расписания по группе и дате.
- Получение расписания по группе и диапазону дат.
- Текстовое представление занятия:
  - предмет;
  - время начала и окончания;
  - преподаватель;
  - аудитория;
  - тип занятия.
- Графическое представление через HTML-шаблон и Playwright.
- Кэширование картинок по ключу `group + date` с TTL.
- Очистка всего кэша и очистка по конкретной группе.

### 4.3 Импорт документов

- Поддержка `.docx`.
- Поддержка `.doc` через внешнюю конвертацию LibreOffice.
- Поддержка диапазонов времени с `-`, `–`, `—`.
- Поддержка дат вида `01.11.25`, `01.11.25 г`, `01.11.25 г Пн`.
- Нормализация типов занятий `(л)` и `(пр)`.
- Извлечение ФИО преподавателя из строки с должностями/аудиторией.
- Идемпотентный импорт: повторная загрузка исправленного файла не создает дубликаты.

### 4.4 Пользователи и аналитика

- Автоматическое создание пользователя при первом событии.
- Сохранение `vk_user_id`, username/имени, группы, времени создания и последней активности.
- Логирование входящих сообщений и callback-событий.
- Счетчики:
  - всего пользователей;
  - активных за день;
  - активных за неделю;
  - популярные действия за период.

### 4.5 Веб-интерфейс и API

- Главная страница с группами, преподавателями, предметами, занятиями.
- CRUD для групп.
- CRUD для преподавателей.
- CRUD для предметов.
- CRUD для занятий.
- Страница загрузки расписания.
- API `/api/groups` и `/api/groups/{id}`.
- Расширяемые API для расписания: `/api/schedule?group=&date=` и `/api/schedule/range`.

## 5. Нефункциональные требования

- Python 3.11+.
- Асинхронная работа с БД.
- SQLAlchemy 2.x + Alembic.
- SQLite для разработки, PostgreSQL для production.
- Конфигурация только через переменные окружения.
- Отсутствие прямых `print` в production-коде после следующего этапа: использовать `logging`.
- Покрытие unit-тестами парсера, сервисов расписания и кэша.
- Явная обработка недоступности Playwright/LibreOffice.
- Отделение доменной логики от транспорта VK/Telegram/Web.

## 6. Целевая модель данных

### User

- `id` — внутренний ID;
- `platform` — `vk`, `telegram`, `web`;
- `platform_user_id` — ID пользователя на платформе;
- `username`/`display_name`;
- `group_id`;
- `created_at`;
- `last_activity`;
- `total_requests`.

### Group

- `group_id`;
- `group_name`;
- связи с пользователями и занятиями.

### Teacher

- `teacher_id`;
- `name`;
- `email`;
- `phone`.

### Subject

- `subject_id`;
- `name`.

### Lesson

- `lesson_id`;
- `start_datetime`;
- `end_datetime`;
- `group_id`;
- `teacher_id`;
- `subject_id`;
- `classroom`;
- `lesson_type`.

### UserRequest

- `id`;
- `user_id`;
- `platform_user_id`;
- `username`;
- `request_type`;
- `request_data`;
- `group_snapshot`;
- `timestamp`.

## 7. Приемочные критерии

- Пользователь VK может выбрать группу и повторно открыть главное меню без повторного выбора.
- Пользователь VK получает расписание на выбранную дату.
- При отсутствии занятий пользователь получает понятное сообщение.
- При падении генерации PNG пользователь получает текстовое расписание.
- Администратор может загрузить `.docx`; занятия появляются в БД.
- Повторная загрузка того же файла не удваивает занятия.
- Очистка кэша по группе действительно удаляет только записи этой группы.
- Приложение запускается без `DB_URL`, используя локальный SQLite.
- SQLite не получает неподдерживаемые параметры пула соединений.
